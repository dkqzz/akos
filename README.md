# Вариант №30: Роботы на складе

Многопоточная имитация автоматизированного склада на C17 для Linux и macOS.
Основная программа использует потоки POSIX, мьютексы и семафоры. Для сравнения в
проекте есть вторая программа с условными переменными.

## Сборка

```sh
./scripts/build.sh
```

Исполняемые файлы находятся в `build/warehouse_sim` и
`build/warehouse_sim_cond`, тесты — в `build/warehouse_tests`.

## Запуск

Основной вариант:

```sh
./build/warehouse_sim --config data/demo.cfg --log demo.log --delay 0
```

Вариант с условными переменными:

```sh
./build/warehouse_sim_cond --config data/demo.cfg --log demo-cond.log --delay 0
```

Доступны параметры:

```text
--config PATH    конфигурация склада
--log PATH       файл журнала
--seed N         начальное значение генератора
--delay MS       задержка между тактами
--max-ticks N    предел числа тактов
--quiet          не выводить события и карту в терминал
--help           справка
```

Демонстрационные запуски:

```sh
./scripts/run_demo.sh
./scripts/run_demo_cond.sh
```

## Многопоточная модель

Главный поток выполняет роль диспетчера и контроллера тактов. Для каждого робота
создаётся отдельный поток POSIX. В начале такта диспетчер назначает ожидающие
задания и будит рабочие потоки. Роботы одновременно выполняют один переход:
движение, ожидание, загрузку, выгрузку или зарядку. После подтверждений всех
роботов контроллер проверяет инварианты, печатает карту и переходит к следующему
такту.

Общее состояние склада защищено мьютексом. Основная программа использует по два
семафора на робота для пробуждения и подтверждения шага. Программа
`warehouse_sim_cond` использует тот же протокол, но заменяет семафоры на
условные переменные. Вывод в терминал и журнал защищён отдельным мьютексом.

## Формат конфигурации

Параметры задаются строками `ключ=значение`. Карта задаётся несколькими строками
`grid=` длиной `width`. Символы карты:

| Символ | Обозначение         |
| ------ | ------------------- |
| `.`    | проход              |
| `#`    | препятствие/стеллаж |
| `P`    | получение           |
| `D`    | выдача              |
| `C`    | зарядка             |
| `N`    | узкий проход        |

```text
width=14
height=8
grid=##############
...
robot=1,row,col,capacity,energy,max_energy
task=101,pickup_row,pickup_col,dropoff_row,dropoff_col,weight
```

Параметры `robot` и `task` можно повторять. CLI имеет приоритет над значениями
конфигурации.

## Завершение и журнал

Работа завершается после разрешения всех заданий, достижения `--max-ticks` или
получения `Ctrl+C`. При прерывании контроллер будит ожидающие потоки, дожидается
их завершения и записывает итоговую строку в журнал.

```text
SUMMARY reason=all tasks resolved ticks=13 assigned=3 completed=3 unreachable=0 moves=26 waits=0
```

Конфигурация `impossible.cfg` демонстрирует корректное завершение с невыполнимым
заданием, а `energy.cfg` - зарядку робота перед движением.

## Тесты

```sh
./scripts/run_tests.sh
```

Проверяются BFS вокруг препятствий, доставка, грузоподъёмность, энергия,
коллизии, загрузка конфигурации, зарядка, потоковый конфликт роботов,
целостность журнала, оба backend-а синхронизации и завершение по сигналу.
